Контекст
Мы разрабатываем собственный компонент шахматной доски для коммерческого продукта с закрытым исходным кодом. Компонент пишется с нуля. Нам нужен рендерер и модель ввода — шахматных правил внутри быть не должно.

Технический стек
* TypeScript, strict: true, без any в публичном API.
* Ядро — framework-agnostic класс на чистом DOM. Никакого React внутри ядра.
* Отдельным пакетом/файлом — тонкая обёртка для React (useEffect + ref, без дублирования логики).
* Целевые браузеры: последние 2 версии Chrome, Safari, Firefox, Edge + iOS Safari.
* Сборка: esbuild или vite в ESM + типы. Тесты: vitest.
* Бюджет: ядро до 12 КБ gzip.

Архитектурные решения — обязательны к исполнению
Это не рекомендации, это принятые решения.


1. Pointer Events, не mouse/touch раздельно. pointerdown / pointermove / pointerup / pointercancel + setPointerCapture(). Один код на мышь, тач и стилус.
2. Позиционирование через transform: translate(), никогда через top/left.
3. Размеры в процентах, чтобы ресайз был бесплатным. Контейнер квадратный (aspect-ratio: 1). Каждая фигура — элемент шириной и высотой 12.5%. Позиция задаётся transform: translate(F00%, R00%), где F и R — индексы 0–7. Тогда при изменении размера доски JS не выполняется вообще, браузер пересчитывает всё сам. Метода resize() в API нет намеренно.
4. Один делегированный обработчик на корневом элементе. Не 64 слушателя.
5. Слои (снизу вверх, отдельные <div>/<svg>): board (фон и клетки) → highlights → pieces → overlays (SVG) → dragged (перетаскиваемая фигура).
6. SVG-слой оверлеев с viewBox="0 0 8 8". Координаты в единицах клеток, разрешение-независимо, при ресайзе пересчёт не нужен.
7. Никаких localStorage, fetch, глобальных переменных. Компонент чистый.

Публичный API — реализуй ровно так
export type Square = string;                  // 'a1'..'h8'


export type PieceColor = 'w' | 'b';


export type PieceKind  = 'p' | 'n' | 'b' | 'r' | 'q' | 'k';


export type Piece      = { color: PieceColor; kind: PieceKind };


export type Side       = 'white' | 'black';


export type Highlight = { square: Square; tag: string };  // tag -> CSS-класс


export type Overlay =


  | { type: 'arrow';  from: Square; to: Square; tag?: string }


  | { type: 'circle'; square: Square;           tag?: string };


export interface InteractionConfig {


  mode: 'none' | 'select' | 'drag' | 'both';


  movableFor: PieceColor[] | 'all';


  /** если задано — фигуру можно отпустить только на перечисленные клетки */


  allowedTargets?: Map<Square, Square[]>;


  allowOverlayDrawing: boolean;


}


export interface BoardOptions {


  orientation: Side;                 // по умолчанию 'white'


  position: string;                  // FEN; допускается только первое поле


  showCoordinates: boolean;          // по умолчанию true


  animationMs: number;               // по умолчанию 180; 0 = без анимации


  dragThresholdPx: number;           // по умолчанию 3


  interaction: InteractionConfig;


  onMoveAttempt?(from: Square, to: Square): void;


  onSquareActivate?(square: Square): void;


  onOverlaysChange?(overlays: Overlay[]): void;


}


export class BoardView {


  constructor(root: HTMLElement, options?: Partial<BoardOptions>);


  setPosition(fen: string, opts?: { animate?: boolean }): void;


  getPosition(): string;


  setOrientation(side: Side, opts?: { animate?: boolean }): void;


  setInteraction(config: Partial<InteractionConfig>): void;


  setHighlights(list: Highlight[]): void;


  setOverlays(list: Overlay[]): void;


  setPendingMove(move: { from: Square; to: Square } | null): void;


  getPendingMove(): { from: Square; to: Square } | null;


  clearSelection(): void;


  destroy(): void;


}


Никаких других публичных методов без согласования. Внутренние — на твоё усмотрение.

Спецификация поведения
1. Позиция и FEN
* Принимай как полный FEN из шести полей, так и одно поле расстановки.
* Для рендера значимо только первое поле. Остальные сохраняй и возвращай из getPosition() без изменений.
* Невалидный FEN: не бросай исключение в конструкторе. Отрендери пустую доску, запиши console.warn с указанием позиции ошибки.
* getPosition() возвращает актуальную расстановку в FEN-формате.
2. Геометрия и ориентация
* Square — строка вида 'e4'. Внутри — индекс 0..63.
* Модуль geometry.ts содержит чистые функции без обращения к DOM: squareToIndex, indexToSquare, indexToRenderCell(index, orientation).
* Смена ориентации меняет только результат indexToRenderCell. Позиция и вся остальная логика от ориентации не зависят.
* При setOrientation(side, { animate: true }) фигуры переезжают анимацией на новые места, а не перерисовываются мгновенно.
3. Диффинг и анимация
При вызове setPosition не перерисовывай доску заново. Алгоритм:


1. Построй карты предыдущая: Square -> Piece и новая: Square -> Piece.
2. Клетки, где фигура совпала по цвету и типу, — не трогай вообще.
3. Для каждой новой фигуры, появившейся на клетке, найди среди исчезнувших фигур того же цвета и типа кандидата-источника. Если кандидатов несколько — выбирай ближайшего по расстоянию Чебышёва. Это считается перемещением: переиспользуй существующий DOM-элемент и анимируй смену transform.
4. Исчезнувшие фигуры без пары — плавно гаси прозрачностью, затем удаляй из DOM по окончании перехода.
5. Появившиеся фигуры без пары — вставляй с нулевой прозрачностью и проявляй.
6. Рокировка обязана выглядеть как одновременное движение двух фигур.


Все анимации — через CSS transition, не через requestAnimationFrame-циклы. При animationMs: 0 и при @media (prefers-reduced-motion: reduce) переходы отключаются полностью.
4. Ввод — единый конечный автомат
Состояния: idle → pressed → dragging → idle, плюс selected.


Нажатие (pointerdown, основная кнопка):


* Определи клетку по координатам указателя.
* Если на клетке фигура, которую разрешено двигать (movableFor) — перейди в pressed, запомни точку старта и клетку, вызови setPointerCapture.
* Если активно состояние selected и нажатие пришлось на допустимую цель — это попытка хода, см. ниже.
* Иначе — сбрось выделение.


Движение (pointermove):


* В состоянии pressed: если смещение превысило dragThresholdPx — перейди в dragging.
* В dragging: перенеси фигуру в слой dragged, центрируй под указателем, на исходной клетке оставь полупрозрачную копию («призрак»). Подсвечивай клетку под указателем.


Отпускание (pointerup):


* Из dragging: определи клетку под указателем. Если она допустима — вызови onMoveAttempt(from, to). Если нет или указатель вне доски — верни фигуру на место анимацией.
* Из pressed (порог не превышен) — это клик: переведи фигуру в состояние selected, вызови onSquareActivate.


pointercancel и Escape: отмена, возврат фигуры, сброс состояния.


Важно: режим 'both' должен работать так, чтобы клик и перетаскивание не конфликтовали. Один и тот же жест не может породить два события.


Ключевой принцип: компонент никогда не двигает фигуру сам. Он только сообщает onMoveAttempt. Хост проверяет ход и вызывает setPosition. Если хост ничего не вызвал — фигура визуально возвращается назад.
5. Отложенный ход (pendingMove)
* setPendingMove({ from, to }) подсвечивает обе клетки тегом pending.
* Любой вызов setPosition сбрасывает отложенный ход в null.
* Escape и нажатие правой кнопкой отменяют отложенный ход. При отмене onMoveAttempt не вызывается.
* Компонент не решает, когда отложенный ход исполнять. Это делает хост.
6. Оверлеи
* Стрелка: линия от центра к центру плюс наконечник-треугольник. Начало линии смещено от центра исходной клетки, чтобы не перекрывать фигуру.
* Круг: окружность по границе клетки.
* Рисование правой кнопкой при allowOverlayDrawing: true: зажатие на клетке → протягивание → отпускание. Отпускание на той же клетке даёт круг, на другой — стрелку. Повторное рисование того же оверлея удаляет его. Каждое изменение — вызов onOverlaysChange с полным актуальным списком.
* Правый клик по пустому месту без протягивания очищает все оверлеи.
* Цвет берётся из tag → CSS-класс. Захардкоженных цветов в TS быть не должно.
7. Доступность
Это не опция, это часть приёмки.


* Корень: role="grid", каждая клетка — role="gridcell" с aria-label вида "e4, white knight" или "e4, empty".
* Ровно одна клетка в tab-порядке (tabindex="0"), остальные -1, фокус перемещается стрелками (roving tabindex).
* Enter / Space — выбрать фигуру или сделать ход на клетку под фокусом.
* Escape — сброс выделения.
* Видимый focus-ring, не убирай outline без замены.
* aria-live="polite" регион, объявляющий совершённые ходы.
8. Стилизация
* Все цвета, скорости и размеры — CSS-переменные с префиксом --bv-.
* Смена темы доски и комплекта фигур должна работать сменой одного класса на корневом элементе, без пересборки и без JS.
* Фигуры адресуются классами вида .bv-piece.bv-wn (белый конь). Конкретные картинки подставляет потребитель через свой CSS.
* Координаты — через CSS-псевдоэлементы, не отдельными DOM-узлами.

Что НЕ входит в задачу
Не реализуй и не предлагай:


* проверку легальности ходов, шах, мат, генерацию ходов;
* разбор PGN, историю партии, дерево вариантов;
* часы, таймеры, рейтинги;
* шахматный движок и любую интеграцию с ним;
* сетевое взаимодействие;
* диалог выбора фигуры при превращении (отдельная задача, обсудим позже);
* 3D-режим.

Критерии приёмки
* dependencies в package.json пуст.
* Ядро ≤ 12 КБ gzip, замерено и указано в README.
* Перетаскивание работает на iOS Safari и Android Chrome на реальном устройстве, без залипаний и без скролла страницы во время перетаскивания.
* Изменение размера контейнера не вызывает ни одного выполнения JS.
* Полный проход по доске с клавиатуры без мыши.
* prefers-reduced-motion отключает все анимации.
* destroy() снимает все слушатели, удаляет DOM, не оставляет утечек (проверить повторным созданием и удалением 100 экземпляров).
* Unit-тесты на: FEN-парсинг и сериализацию, geometry.ts, алгоритм диффинга (включая рокировку и взятие), автомат ввода.
* demo/index.html показывает доску, позволяет двигать фигуры, рисовать стрелки, флипать доску и загружать произвольный FEN.
